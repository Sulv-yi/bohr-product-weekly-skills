# 对得上：目标、路线、指标、成果的四元组

## 1. 一条链，四个节点

```
问题 Q → 目标 G → 路线 R（输入/处理/输出） → 指标 M（可考核） → 成果 O（交付形式）
```

"对得上"就是这条链**不缺环**：每个目标都有路线、有指标、有成果；
指标在正文里能找到同款表述（正文与结构表不能各写各的）。

## 2. 为什么用结构化表而不是只在正文里叙述

正文叙述里的对应关系读者要自己拼，评审常拼不出来。所以本 Skill 要求
稿件之外落一份 `plan`：

```json
{
  "goals": [{"id": "G1", "question": "Q1", "route": "R2",
             "metric": "孔隙率 ≥70%", "outcome": "O1", "deadline_month": 9}],
  "routes": [{"id": "R2", "step": "微型CT测孔隙率 + 单轴压缩测模量",
              "input": "R1 试样", "output": "每组均值与标准差"}]
}
```

`alignment_rate` = 四元组齐全的目标数 / 目标总数。

## 3. 三类常见断裂

| 断裂 | 现象 | 后果 |
|---|---|---|
| 目标无路线 | G2 写"建立剂量-响应曲线"，路线里没有对应步骤 | 评审问"怎么做" |
| 目标无指标 | G1 写"评价力学性能"，没有阈值 | 无法考核，等于没定目标 |
| 指标与正文不符 | 表里写"孔隙率 ≥70%"，正文写"孔隙率约 75%" | 读者不知道哪个是判据 |

第三类最隐蔽：脚本会检查指标串的前几个字是否在正文出现，找不到就标"正文未呼应指标"。

## 4. 指标要可考核

| 不可考核 | 可考核 |
|---|---|
| 评价支架的力学性能 | 压缩模量 ≥8 MPa（ISO 13314，1 mm/min） |
| 探索成骨效果 | ALP 活性较对照提高 ≥30%（第 14/21 天，重复 3 批） |
| 建立预测模型 | 拟合 R² ≥0.9，95% CI 报出 |

## 5. 成果要写出交付形式

`O1` 不写"数据集"，写"三组支架的结构-力学-压电数据集（每组 n = 24），
以数据表与图 1–图 3 交付，考核方式为组内变异系数与组间差异检验"。

## 6. 路线要写输入输出

一条路线步骤 = 输入 + 处理 + 输出。只写处理（"测孔隙率"）的步骤无法与前后对接，
也无法判断关键路径。写出输入输出后，串行依赖自然浮现：

> R1→R2→R3 为串行依赖，R4 与 R3 后半段可部分并行；R1 的工艺定型是 R2 全部指标的前提，属关键路径。
