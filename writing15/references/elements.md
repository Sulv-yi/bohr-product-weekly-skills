# 七要素：每一节写什么、写多少

七要素是硬门槛：缺一节，评审读到的就不是开题报告而是研究计划草稿。

| 要素 | 最少字数 | 必须回答 | 常见失败 |
|---|---|---|---|
| 研究背景与立项依据 | 350 | 已知（挂引用）→ 未知（缺口）→ 待验证（本课题） | 把领域综述一遍，读完不知道缺口在哪 |
| 研究问题与可证伪假设 | 150 | 指标 + 阈值 + 对照/时间点 | "探究 X 的影响"，无法被数据推翻 |
| 研究目标 | 150 | 每个问题对应 1–3 个可考核目标 + 交付时点 | 目标与问题数量不对应，或目标写成了动作 |
| 技术路线 | 300 | 每步的输入 → 处理 → 输出；串行依赖与关键路径 | 罗列方法名，不说输入输出 |
| 阶段计划 | 150 | 起止月 + 工作量（人月），合计 ≤ 可用人力 | 只写"分三阶段"，无月份无工作量 |
| 风险与备选方案 | 150 | 触发信号 + 影响范围 + 备选方案 + 决策时点 | 只写"可能遇到困难" |
| 预期成果与考核方式 | 120 | 交付形式 + 怎么算达标 | 写"发表论文"却不写几篇、什么标准 |

## 字数怎么算

按 `_nchars`：中文按字、西文按词 ×0.6、数字按个 ×0.6。参数密集的技术路线不会因为
中文少而被判不足，但纯罗列方法名的段落一定不够。

## 节名要对得上检查表

`proposal_gate.ELEMENTS` 用正则识别节名。可用写法：

- 背景：`研究背景`、`立项依据`、`背景`
- 问题：`研究问题`、`问题定义`、`科学问题`
- 目标：`研究目标`、`目标`
- 路线：`技术路线`、`研究方案`、`方法`、`approach`
- 计划：`阶段计划`、`进度`、`时间安排`、`里程碑`
- 风险：`风险`、`risk`
- 成果：`预期成果`、`预期结果`、`考核`、`deliverables`

节名写成"一、研究背景"或"## 1. 研究背景"都能识别；写成"关于本课题的背景思考"识别不到，
会被判缺项——这不是吹毛求疵，评审找节也是按这个名字找。

## 要素之外还该有的两节

- **数据与材料可得性**：数据何时归档、以什么形式共享、有何限制。开题报告常被要求写。
- **经费预算**（若指南给了上限）：分项合计必须等于总额，否则"排得开"就是假的。

## 与"对得上""排得开"的关系

七要素齐只是入场券。真正的分差在：

- 目标 G1/G2/G3 是否各自挂到一条路线、一个指标、一项成果（见 `alignment.md`）；
- 阶段计划的工作量是否 ≤ 可用人力（见 `schedule-feasibility.md`）。
