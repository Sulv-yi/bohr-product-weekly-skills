# 与已有方案的边界

这一节回答一个问题：**本 Skill 到底补了什么，哪些事它不该做。**
只写有依据的比较；没有实测过的对象，不声称优于它。

## 1. 比较对象与适用位置

| 方案 | 擅长 | 在本任务上的缺口 | 本 Skill 的位置 |
|---|---|---|---|
| 基础 Agent（不加载 Skill） | 通用行文、把要点串成段落 | 章节常缺 3–4 类（数据可得性、声明字段几乎不写）；题注与正文提及不成对；正文数值无法回溯到材料；引用编号与文献表不对应 | 把章节清单、图表配对、引用闭合、数值可回溯变成可计算的门槛，不达标不能定稿 |
| 论文模板向导 / 填空式写作工具 | 给出标准章节骨架 | 骨架能过，内容不能：留空标题也算「章节齐全」，图表编号与正文不联动，声明字段照抄模板 | 骨架只作为形态保证（`draft_skeleton.py`），能否定稿由字数、配对、闭合、回溯四项判定 |
| 文献管理工具（Zotero 等） | 条目真实性与著录格式 | 不判断文献是否支撑该句；也不管正文数值来自哪张表 | 材料索引把「论断 → 材料位置/文献条目」显式化，二者串联使用 |
| 通用查重/一致性检查 | 文字重复、格式规范 | 不检查「正文 62% 与图上 60% 是否为同一数」这类跨对象一致性 | `num_trace_rate` 逐值回溯；`fig_pairs` 检查题注与正文提及是否成对 |

## 2. 新增能力的落点

1. **材料索引先于正文**（`references/material-index.md`）：先建「数值 → 材料位置」的对照表，
   再写正文。基础 Agent 的写法是先写正文、再补引用，必然出现无出处的数值。
2. **数值可回溯率**（`sections_gate.num_trace_rate`）：把正文所有「数字 + 单位」逐个拿到
   索引与来源的 `quote` 里比对，找不到的列进自检表。这是本题「事实一致性」的直接抓手。
3. **图表双向配对**（`fig_pairs` / `tab_pairs`）：正文提及集合与题注集合取交集，
   孤立题注单独报出来。只有一侧存在都不得分。
4. **章节门槛按技术文本密度设定**：字数口径把数字按个 ×0.6 计入，避免「参数写得很实」
   的方法节被判成篇幅不足，也避免为了过门槛注水。

## 3. 明确做不到的

1. **不判断学术贡献大小**。章节齐、引用闭合不等于工作有价值；这部分无法脚本化。
2. **不做文献检索**。只处理材料里给出的文献；材料没给的不去编，缺的在 `uncertainty` 写明。
3. **不做统计复核**。只检查数值是否与材料一致，不判断统计方法选得对不对。
4. **不做期刊排版**。输出是可编辑 Markdown，投稿排版需在 Word/LaTeX 里完成（见写作13）。
5. **跨语言一致性只做弱校验**。中英混排时西文按词折算，语义级对齐靠人工。

## 4. 与本题评分维度的对应

- 实际效果：靠章节齐备度、引用闭合、图表配对、数值回溯四项硬指标；
- 使用增益：靠 A/B 对照（同材料、同题目、同字数要求），变差项如实列出；
- 创新增益：靠「索引先于正文」与「数值回溯」两个基础 Agent 不做的事；
- 可靠体验 / 生态贡献：靠异常矩阵、目录式文档与可替换的门槛表。

边界写在这里的意义是：评审可以据此判断哪些分是本 Skill 挣的，哪些不是。
