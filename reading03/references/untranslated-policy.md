# 未译与不确定性标注规则（Untranslated / Uncertainty Policy）

## 原则
**译不准要标明，不能含混处理。** 科研翻译里"看似通顺但错了"比"明确标出不会"危害更大——前者会让读者误信错误结论。

## 何时标 `untranslated`
在段落的 `untranslated` 数组里记录存疑片段，每条含 `span`（原文片段）+ `reason`：
- 原文该处是图片 / 扫描模糊，无法辨识
- 专业术语无可靠对应译名
- 公式为图片，符号无法转写
- 原文残缺、缺字、OCR 乱码
- 跨语言混杂（如英文句中嵌中文/德文引文）

## 何时写 `uncertainty`（整体级）
- PDF 无文字层，仅能做有限翻译 → `status: partial`，说明需 OCR
- 术语表存在冲突口径，无法唯一确定
- 引用 / 图表编号在原文本身就不一致
- 语义级误译风险高（脚本只能查硬损伤，指代/语气需人工复核）

## 状态取值
| status | 含义 |
|---|---|
| `success` | 任务范围内全部完成，守恒核验通过 |
| `partial` | 部分完成（如无文字层、部分图片公式未译），已标明限制 |
| `unable` | 材料不可用，无法给出译文，给原因与接管位置 |
| `refused` | 任务超出能力或不符合约束，给原因 |

## 反例（禁止）
- 把看图猜的内容写成确定译文
- 把 `not` 丢失后仍报 `success`
- 把未译片段悄悄跳过、不写 `untranslated`
- 编造文献编号或实验数值来"补全"译文
