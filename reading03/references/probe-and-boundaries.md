# 输入探查与任务边界（Probe & Boundaries）

## 先读实际文件，不从标签推断
题面明确要求：`实际输入文件和原论文是事实依据；不依据错误的领域标签补造数据。` 因此：
1. 先跑 `probe_pdf.py <pdf>` 看页数、文字层、语言
2. 真正打开原文读内容，确认任务范围（全文 / 指定段落区间）
3. 再从原文抽取术语、分段、翻译

## PDF 探查要点
- **有无文字层**：`probe` 结果里 `has_text_layer` 为 false → 扫描件，需 OCR，状态 `partial`
- **页数与语言**：确认是英文文献；混杂语言在 `uncertainty` 说明
- **加密 / 乱码字体**：识别出来并说明，不臆造
- **降级链**：PyMuPDF → pdfplumber → pdftotext → 标准库兜底（`pdf_fallback.py`，若提供）

## 任务边界识别
读 `case.json` 的 `output_contract` 与 `task.md`，确认：
- 翻译范围：全文还是指定段落
- 语言方向：英→中（默认）还是其他
- 输出契约字段：必须有 `case_id` + 全部 `output_contract` 字段
- 是否需要术语表作为交付项

## 材料异常处理
| 情况 | 处理 |
|---|---|
| 无文字层扫描件 | 状态 `partial`，说明需 OCR |
| 公式 / 表格为图片 | 保留编号，正文说明未识别 |
| 原文残缺 | 可译部分正常译，残缺段标 `untranslated` |
| 语言混杂 | 逐语言处理，说明口径 |
| 任务字段缺失 | 在 `uncertainty` 写明缺失项，不猜 |

## 资源限制
≤50 个 UTF-8 文本文件、单文件 ≤500KB、总量 ≤2MB、无符号链接。脚本尽量小而完整，不打包大型依赖。
