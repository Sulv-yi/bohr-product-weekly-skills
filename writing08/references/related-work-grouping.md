# 相关工作分组与比较框架

## 为什么分组

逐篇摘要拼接是常见失败：读者看不出立场，也看不出本文位置。相关工作要按**比较维度**组织，在同一维度上对比取舍。

## 可选分组方式（按任务择一或组合）

| 分组依据 | 适用 | 组名示例 |
|---|---|---|
| 问题设定 | 任务定义有分歧 | "面向单模态的方法" / "面向多模态的方法" |
| 方法路线 | 技术路线清晰 | "基于监督微调" / "基于强化学习" / "基于检索增强" |
| 数据与评价 | 评测方式差异大 | "使用公开基准的方法" / "自建数据集的方法" |
| 共享假设 | 有共同前提 | "依赖人工标注的方法" / "无需标注的方法" |

## 每组的写法（固定四步）

1. **共同做法**：这一组共享什么思路（1 句）。
2. **各自取舍**：组内各工作在该思路下的具体选择与代价（附引用）。
3. **遗留问题**：这一组整体没解决什么（附来源或标作者判断）。
4. **与本文关系**：本文沿用什么、改变什么（指向本文证据）。

## 禁止

- 按发表年份流水账罗列。
- 只写"X 提出了…；Y 提出了…"without comparison。
- 转述他人结论时改变适用条件或强度（"可能"写成"证明"、"在该数据集上"写成"普遍"）。
- 把他人结果当本文结果。

## 分组结果自检

- 每组是否都在同一维度上可比？
- 关键工作是否都被覆盖（对照 sources 清单）？
- 每个论断是否都能回到具体文献？
