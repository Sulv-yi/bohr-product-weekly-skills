# 与已有方案的边界

这一节回答一个问题：**本 Skill 到底补了什么，哪些事它不该做。**
只写有依据的比较；没有实测过的对象，不声称优于它。

## 1. 比较对象与适用位置

| 方案 | 擅长 | 在本任务上的缺口 | 本 Skill 的位置 |
|---|---|---|---|
| 基础 Agent（不加载 Skill） | 通用行文、把要点串成段落 | 四部分常被压成两段；相关工作按文献逐篇摘要；空白写成"仍有研究空间"；引用是装饰而非论据；无法说明哪句论据来自哪篇 | 把四要素、分组数、空白推导链、贡献-证据对应变成可计算的门槛，不达标不能定稿 |
| 文献管理工具（Zotero/EndNote 的综述草稿功能） | 管元数据、批量插入引用、按模板出参考文献表 | 只保证"引用格式对"，不判断"这句论断该不该引这篇"；不比较各工作的取舍；不产生研究空白 | 只管引用与论断的绑定关系，元数据仍交给文献管理工具 |
| 通用写作助手（润色/扩写类） | 语言流畅、段落衔接 | 会把无来源的判断写成断言；扩写时补出材料外事实；不区分他人结论与作者判断 | 先建事实底稿再写作，禁止材料外事实，判断句须标注为作者判断 |

结论：本 Skill 不与上述方案竞争"文笔"，它竞争的是**可核验性**——
成稿交付时能同时说清"这句论据出自哪篇、这条空白由哪些工作的限制推出、这条贡献对应哪个图表"。

## 2. 基础 Agent 难以稳定做到的四件事

1. **四要素各自成段且彼此承接**
   骨架脚本先落四段，再逐段填真实内容。基础 Agent 直接写全文时，
   "研究空白"最容易被压缩成一句过渡句，而它恰恰是评分里"说得实"的落点。

2. **相关工作按维度分组，而不是按文献顺序**
   分组框架固定为「共同做法 → 各自取舍 → 遗留问题」三段式，
   组数可数（`related_groups`），少于 3 组在 `validate_result.py` 里直接报错。
   基础 Agent 往往把"某某等人提出…"按年份排成一段。

3. **空白必须由已引文献推出**
   检测的是推导链是否存在：既要有"共同限制/未覆盖/冲突"这类限制词，
   又要有落到本文的对齐表述（`gap_chain_present`）。缺任一环就提示补写。

4. **贡献条条带证据定位**
   每条贡献必须给出 `§/Fig./Table/实验结果` 之一，
   `contribution_evidence_rate` 未达 100% 会提示，避免"本文提出了新方法"式空条。

## 3. 方法取舍（为什么这样做）

| 取舍 | 选择 | 理由 |
|---|---|---|
| 先后顺序 | 先落骨架，再填内容 | 空壳与大纲是 0 分的主因；骨架保证中断时也留下结构完整的半成品 |
| 写作与核对 | 两遍分离，先写后核 | 边写边凭记忆填引用，是最容易造出假元数据的路径 |
| 记录方式 | claim/file/page/section/quote 五元组 | 只有能回到页码与原文，复核人才不必信任作者 |
| 自评 | 用脚本算结构指标 | 文字自述不可复核；同一输入重跑同一脚本才能对照 |
| 来源缺失 | 宁可标 partial 并写入 uncertainty | 编一个来源比缺一个来源更难被发现，也更伤可信度 |

## 4. 不声称的部分

- 不声称在文学性或论证创意上优于人工写作；它做的是结构约束与来源绑定。
- 不声称跨学科无需调整：分组维度与空白类型需按领域替换（见 `references/related-work-grouping.md`）。
- 不声称零人工：`manual_review_items` 允许非零，那是诚实缺口而不是失败。
- 不声称已在平台固定案例上取得某个具体分数；本文件只描述能力边界。
