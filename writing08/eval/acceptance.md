# 验收标准与盲评表

这是给「人」看的判定口径，与 `eval/rubric.json`（给机器看）一一对应。
用途两个：开发期自查；盲评时作为唯一评分依据，避免评分人各用各的标准。

## 1. 硬门槛（任一不过即不合格）

| 编号 | 门槛 | 判定方式 |
|---|---|---|
| H1 | 四要素（背景/相关工作/空白/贡献）各自成段且顺序正确 | `four_part_coverage == 1.0` |
| H2 | 相关工作按 ≥3 组比较，每组都写了共同做法、取舍与遗留问题 | `related_groups >= 3` + 人工确认三段式 |
| H3 | 空白由已引文献的限制推出，并说明本文如何对应 | `gap_chain_present == true` |
| H4 | 每条贡献都有正文证据定位（§/Fig./Table/实验结果） | `contribution_evidence_rate == 1.0` |
| H5 | 每条来源都能回到 file/page/section/quote，且不与正文论断错配 | `source_metadata_rate >= 0.8` + 抽查 `source-map.csv` |
| H6 | 定稿无占位符、无材料外事实 | `placeholder_count == 0` + 人工抽查 |

## 2. 盲评表（主观项，5 分制）

评分人不知道版本来源，只按下列五项各打 1~5 分。

| 项 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 立得住 | "近年来受到广泛关注"式空转 | 说明了领域重要性但未指向具体问题 | 交代了领域脉络、具体未解问题与技术约束 |
| 分得清 | 逐篇摘要拼接 | 有分组但比较维度不统一 | 同一维度下比较各工作取舍，并给出遗留问题 |
| 说得实 | 空白是断言 | 空白有依据但推导跳跃 | 空白由已引工作的共同限制/冲突结论推出，并落到本文 |
| 对得上 | 贡献与图表无关 | 大体对应但有用词夸大 | 每条贡献都能在正文找到对应证据，范围表述克制 |
| 引用覆盖 | 关键工作缺失或元数据错 | 覆盖主要工作但近期进展不足 | 关键、代表性与近期工作都覆盖，编号与元数据可逐条核 |

判定：五项均值 ≥4.0 且无单项 ≤2，视为「可用」；否则退回修改。

## 3. 分歧处理

- 两位评分人对同一项差 ≥2 分时，必须写出分歧理由（引用具体句子）。
- 分歧项单独记录，不用平均掩盖。
- 分歧超过 2 项，说明评分表本身有歧义，先改表再评。

## 4. 不许做的事

- 不拿本 Skill 作者的自评分当验收结果。
- 不把 `examples/` 里的示例成绩写成正式案例成绩。
- 不为凑 `manual_review_items = 0` 而隐藏真实缺口——该问作者的要问。
- 不为了让 `claim_binding_rate` 好看，把不需要引用的句子硬塞引用。
