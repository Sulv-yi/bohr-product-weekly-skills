# 论文结论核对（paper-claim-audit）

## 何时使用

- 要把某篇论文的数值写进综述、方案、专利或自己的实验设计；
- AI 已经给了一份读后摘要，需要判断能不能直接引用；
- 论文摘要里的 "outperforming / first / superior" 之类表述要落到具体条件；
- 需要把"读了什么、核了哪些、还缺什么"留成可复查的记录。

不适用：需要判断论文机理是否成立、需要复现实验、需要读通整篇综述型长文。

## 输入

| 输入 | 必需 | 说明 |
| --- | --- | --- |
| PDF（或已抽取文本） | 是 | 优先取开放获取原文；无权限时用合法片段，但要标来源与页码 |
| 阅读问题 | 否 | 缺省为"这些结论能否外推到我关心的体系" |
| 指标词表 | 否 | 缺省覆盖 relative density / cell size / MFI / 减重四类，可扩展到模量、电导率等 |

## 执行步骤

1. **抽取保页码**：把 PDF 转成带 `<!-- page N -->` 锚点的 Markdown；只清残留噪声
   （行末断词的软连字符、`◦`→`°`），不改写句子。跑 `scripts/clean_extract.py`。
2. **结论绑定**：把每条带数字的结论写成一行 `claim_id, subject, metric, value, page, quote, claim`。
   `quote` 逐字复制、不拼接、不跨页；摘要里的数与结果段的数分开记。
3. **建证据底账**：把正文里能承载该指标的句子收进 `page, subject, metric, value, quote`。
   这一步是人工的，但可逐行审计——底账错了，后面的覆盖判断就没意义。
4. **跑核对**：`scripts/claim_check.py` 判五项：引文逐字命中、页码一致、声明数值在引文内、
   口径词一致、底账中同料名数值是否越出声明区间。
5. **回原文处理 FAIL/CONFLICT**：对每条失败项回答四问——成立条件是什么、另一个数是条件不同
   还是口径不同、对照臂与实验臂是否同规格、准确的带限定写法是什么。写进复核记录。
6. **补三项人读检查**：摘要比较级有无同条件证据；同一物理量是否换了口径
   （相对密度 / 密度 / 重量 / 体积膨胀）；first/only 有无检索范围，没有就降级为"作者主张"。

## 输出

```
evidence/claims.csv      我读出的结论（待核）
evidence/corpus.csv      证据句底账（对照集）
evidence/check.csv       每条结论的机器判定
evidence/check.md        汇总报告：哪些要改、为什么
evidence/manual_verify.md 人工复核：条件、对照臂、口径、写法
```

## 质量检查

- 底账错误数必须为 0，否则先修底账再看结论；
- 每条 FAIL 必须在复核记录里有对应的"准确写法"，只指出问题不算完；
- 结论清单里每条都要有页码；跨页引文退回重取，不要拼接；
- 报告里要写清没核的部分（未取得的支撑信息、未覆盖的指标），不许用"已核对"概括全篇。

## 适用边界

- 只处理**能定位到原文**的数值型结论；定性论断（机理、机理解释）不在此列。
- "对照臂不对称"这类判断依赖领域常识，脚本不判，必须人读并记录依据。
- 反向情况：论文数值本身就在支撑信息里（本次的 0.28、完整 Table S1），拿不到 S1 时
  只能标"证据缺口"，不能判"错误"。
- 单篇、单次运行不构成统计证据；不要据此声称"该方法普遍提升阅读质量"。
