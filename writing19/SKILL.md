# 证据可追溯的思维导图

导图的失败很少是"画得不好看"，而是三件看不出来的事：
**节点回不到原文**、**层级忽深忽浅**、**关系是脑补的**。
这三件事人眼扫一遍很难发现，工具一跑就现形。这个 Skill 的取舍是：
在"好看"和"站得住"之间，先保证站得住。

## 何时使用 / 不使用

**使用**：把一篇论文/综述/技术报告整理成结构图；把多份材料合成一张研究问题图；
把实验方案或项目计划整理成可推进的依赖图。
**不使用**：需要视觉设计的演示用图（用图形摘要流程）；需要逐字翻译（翻译类任务）；
材料本身不足 300 字（信息量不够成图，直接给摘要更诚实）。

## 输入 / 输出契约

输入（按平台案例给的形式取其一）：
- `/input/case.json` + 材料文件（`.md` / `.txt` / `.pdf`）
- 或直接给材料路径

输出（`/app/output` 下）：
| 文件 | 用途 |
|---|---|
| `mindmap.mm` | FreeMind / XMind / MindMaster 可直接打开继续改 |
| `mindmap.opml` | 大纲工具通用交换格式 |
| `mindmap.md` | 纯文本大纲，diff 友好 |
| `mindmap.svg` | 矢量预览，节点上标着证据编号 |
| `result.json` | 平台契约字段 + 主结果 + 证据 + 不确定 |
| `blocks.json` / `blocks.md` | 句子块底账，复核用 |
| `check.md` | 自查报告（10 项） |

## 六步流程

### 第 1 步：编号，不急着画

```bash
python3 scripts/mm_scaffold.py --in <材料> --out work --title "<标题>"
```

得到 `work/blocks.json`：每句一个 `P页-S句` 编号，附带 `hints`（句式线索）、
`noise`（页码/页眉/参考文献条目）、`heading`（章节标题）、`table`（表格行）。

**先读 `blocks.md`，不要读原文全文**。759 句的论文读 blocks 清单比读原文快 6 倍，
而且你引用的每个编号都能被脚本验证。

### 第 2 步：定类型（六类，只有六类）

| 类型 | 收什么 | 判定线索 | 不收什么 |
|---|---|---|---|
| `question` | 研究问题、假设、明写的缺口 | 问句、aim/we investigate、remains unclear、knowledge gap | 泛泛的"具有重要意义" |
| `method` | 材料、试样、仪器、流程、参数、表征手段 | 采用/制备/测试/we used、具体参数 | 方法的意义（那属于结论） |
| `evidence` | 有数值、图表、对照的结果 | 数字+单位、Fig/Table 引用、误差、显著性 | 没有出处的"效果显著" |
| `conclusion` | 作者对结果的解释、机制、外推 | 表明/因此/indicate/suggest、机制动词 | 重复结果的句子 |
| `limitation` | 局限、边界、未做、样本不足 | 仅/未能/limited to/further work | 客套的"仍需努力" |
| `task` | 明确的后续动作、待办、里程碑 | 需要/计划/next step/must | 作者的愿望 |

一条句子只归一类；跨类的拆成两个节点，各自挂同一 block。
装饰性句子（"近年来受到广泛关注"）**不进图**——它们让图变长，不让人更懂。

### 第 3 步：命名（节点名的四条硬规则）

1. **8–34 字**，超过 34 字脚本会截断，正文挂 note。
2. **不得以连接词开头**：However / 此外 / 因此 / Finally / In contrast 开头的节点等于没写。
3. **不得整句搬运**。中文取"动宾"或"名词+限定"，英文取主句主干：
   - ✗ `the results show that the relative density decreases with foaming temperature`
   - ✓ `相对密度随发泡温度升高而下降`
4. **同类同粒度**：同一父节点下，子节点要么都是"结论句"，要么都是"子主题"，
   不要一条结论、一条方法、一条页码混排。

### 第 4 步：搭层级（有硬上限）

```
根：材料主题（≤34 字）
├─ 一级：类型分支（最多 6 个，缺类不补）
│   ├─ 二级：子主题（同一类里按材料顺序或机制聚类，≤7 个）
│   │   └─ 三级：具体节点（≤7 个，必须是可独立引用的判断）
```

- **深度 ≤4**（含根）。第 5 层说明你在做正文复述，不是做图。
- **扇出 ≤7**。超过就说明该层没有归并，先合并再加。
- **同级标题长度离散度 ≤0.55**（脚本会算 CV）。一条 8 字、一条 40 字，读起来就散了。

### 第 5 步：连关系（七型，每条要有依据）

| 类型 | 含义 | 依据线索 |
|---|---|---|
| `cause` | A 导致 B | 因此/使得/导致/lead to |
| `depend` | B 成立需要 A | 基于/依赖/前提/after |
| `contrast` | A 与 B 对照 | 相比/而/whereas/in contrast |
| `sequence` | 时间或步骤先后 | 先/再/随后/before/after |
| `cite` | B 引用/来自 A | [n]、(Author, year) |
| `support` | B 支撑 A 的判断 | 同一段内的证据句 |
| `conflict` | A 与 B 不一致 | 矛盾/与…相反/contradict |

**每条关系必须有 `evidence`**（一个 block 编号）。说不出依据的关系不要连——
图上多一条虚线，读者就少信一分。关系总数 ≥3，宁少勿滥。

### 第 6 步：校验，不过就改

```bash
python3 scripts/mm_check.py --blocks work/blocks.json --nodes work/nodes.json --out work/check
```

10 项全过才算交付。退出码 1 表示有 FAIL，**按 check.md 的条目改 nodes.json 再跑**，
不要靠写说明文字绕过。

| 项 | 挡住什么 |
|---|---|
| C1 schema | 缺字段、id 重复 |
| C2 树结构 | 多根、环、父不存在 |
| C3 覆盖 | 缺方法/证据/结论；缺局限且没登记不确定 |
| C4 类型 | 自造类型 |
| C5 标题 | 过短过长、空话、同父重复、重复标点 |
| C6 证据 | 引用了不存在的块；非根节点没证据 |
| C7 数字 | 标题里的数字在所挂原文找不到（截断容忍） |
| C8 层级粒度 | 深度>4、扇出>7、同级长度离散 |
| C9 关系 | 少于 3 条、端点不存在、类型非法、无证据 |
| C10 推断 | 标了 inference 却没登记不确定 |

### 第 7 步：导出

```bash
python3 scripts/mm_export.py --nodes work/nodes.json --blocks work/blocks.json \
    --out /app/output/mindmap --title "<标题>"
```

四种格式一次出。`.svg` 里每个节点右下角带 `P页-S句`，评审可以照着编号回原文。

一键版（含兜底草稿）：

```bash
python3 scripts/mm_run.py --case /input/case.json --work /app/work --out /app/output
```

**注意**：`mm_run.py` 的 `draft_nodes()` 是"没有 Agent 时"的兜底，标题来自句子截断，
语义质量明显低于人工改写。**Agent 应把它当骨架，重写 title 与 relations 后再跑 check**，
不要直接把草稿交上去。

## 三种如实标注（不写就等于造假）

1. **`level` 三态**：`fact`（原文直读，有数字/引用）、`summary`（跨句概括）、
   `inference`（跨段推断，材料没直接连）。`inference` 必须进 `uncertainty`。
2. **材料缺问题句**：不建 `question` 分支，在 `uncertainty` 写明"材料未显式陈述研究问题"。
   脚本的 C3 会因此放行，但报告里会留痕。
3. **材料缺页**：`blocks.json` 里 `page=0`，`result.json` 的 `status` 写 `partial`，
   并在说明里写"未保留页码锚点，定位精度下降"。

## 异常处理

| 情况 | 处置 |
|---|---|
| 只有 PDF、抽不出文本 | 先试 `pdf-text-tool`；失败则输出 `result.json` 的 `status=blocked` + `reason=no_readable_material`，不编内容 |
| 材料无页码锚点 | 用 `P0-Sn`，在 result 里标 `page_missing` |
| 单段超长（>12000 字） | scaffold 自动按句边界二次切块 |
| 表格被当正文 | scaffold 标 `table=true`，draft 不用它做标题，但可作 evidence |
| 材料自相矛盾 | 两个数都进节点，关系用 `conflict`，不确定性写清"两个数字来自不同段落" |
| 节点爆炸（>80） | 说明该归并没做：先合并同级，再考虑拆图 |
| 重复材料（多版本） | 按最新版本建图，旧版本差异进 `uncertainty` |

## 与基础 Agent 的对照怎么做

同一材料、同一任务、同一预算，两次运行：

| | 基础 Agent（A0） | 本 Skill（A1） |
|---|---|---|
| 流程 | 一句"帮我画个思维导图" | 六步 + 校验 |
| 证据 | 不标 block | 每节点挂 P页-S句 |
| 数字 | 凭记忆写 | C7 强制回原文比对 |
| 层级 | 随手分层 | 深度/扇出/CV 有上限 |
| 关系 | 不画或全画成"相关" | 七型 + 每条带依据 |

对照结果写进 `examples/ab-report.md`，只写实测数字，不写"显著提升"这类词。

## 限制

- 脚本不做语义理解，兜底标题是句子截断，**必须人工或 Agent 改写**。
- 中文不依赖分词库，长术语（>20 字）会被截断，需要在 note 里补全称。
- 影像/光谱类图无法从文字材料还原，只能引用作者的读图结论。
- `.svg` 是自绘布局，超过 60 个节点会横向拉长，建议拆成多张图。
