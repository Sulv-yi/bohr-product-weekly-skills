# 证据可追溯的思维导图：材料 → 可编辑、可核对的图

一个能被 Agent 调用的 Skill：把论文/综述/方案整理成思维导图，
**每个节点都挂回原文的 `P页-S句`，每条关系都写明依据类型**，
并用 10 项自查在提交前挡住三类硬伤：回不到原文、层级失控、关系无据。

## 一、要解决的具体问题

导图最容易出问题的地方不是"画得难看"，而是三种**看不出来**的错：

1. **节点回不到原文**。图上有"相对密度最低达 0.20"，原文写的是 0.17——
   这种错人眼扫图发现不了，回到原文逐条对又要半天。
2. **层级失控**。同一个父节点下，一条是"结论"，一条是"页码"，一条是"方法"，
   读者读到第三层就不知道自己在看什么。
3. **关系是脑补的**。图上画了"导致"，原文两段之间只隔了一个空行。

这三件事都能**从结构上量出来**，所以这个 Skill 的做法是：
先给原文每句编号，再用硬约束（证据必挂、深度≤4、扇出≤7、关系必带依据）
把错误变成"跑不过的检查"，而不是"看不出的瑕疵"。

## 二、做法：六步，脚本管结构，Agent 管语义

| 步 | 做什么 | 工具 |
|---|---|---|
| 1 | 材料切块编号（`P页-S句`），标出噪声/标题/表格 | `scripts/mm_scaffold.py` |
| 2 | 按六类归位（问题/方法/证据/结论/局限/任务） | Agent 按 `SKILL.md` |
| 3 | 命名（8–34 字、不整句搬运、不以连接词开头） | Agent |
| 4 | 搭层级（深度≤4、扇出≤7、同级粒度齐） | Agent |
| 5 | 连关系（七型，每条带 evidence） | Agent |
| 6 | 10 项校验 → 导出四种格式 | `mm_check.py` / `mm_export.py` |

一键兜底：`scripts/mm_run.py`（没有 Agent 时也能出结构完整的图，但标题是句子截断，
语义质量明显低于改写版，`SKILL.md` 里已明确要求 Agent 在草稿上改而不是直接交）。

分工的理由：脚本做不了"这句话算方法还是算结论"，但它能做"这个数字有没有出处"；
Agent 反过来。让各自做能做的，比让模型一个人扛全部更稳。

## 三、实测结果（2026-11-25，材料：Merillas 2026, *Mater. Today Sustain.* 34:101352）

同一份材料（12 页 / 759 句 / 57,785 字），两次运行的对比：

| 指标 | 脚本兜底草稿 | 按 SKILL 改写 | 变化 |
|---|---|---|---|
| 节点数 | 32 | 20 | −12（去掉过渡句与重复） |
| 关系数 | 20 | 6 | 20→6，全是跨支真实关系 |
| 关系类型数 | 4 | 5 | 增加 `conflict` |
| 证据覆盖 | 100% | 100% | 持平 |
| **以连接词开头的节点** | **11** | **0** | 读不通的标题清零 |
| 碎片节点（<10 字） | 6 | 3 | 只剩 3 个分类节点 |
| 标题长度离散度（CV） | 0.44 | 0.23 | 同级粒度变齐 |
| 自查通过项 | 10/10 | 10/10 | 脚本兜底也能过结构关 |

两类真实缺陷被脚本当场抓住：

1. **人工也会写错数字**。改写时我把 PET_C 的最低相对密度写成 0.20，
   `mm_check.py` 的 C7 比对原文块 `P10-S48`，报出「0.20 在所挂原文里找不到」；
   回原文后改成 0.17（15 MPa 时为 0.18）。这条如果只靠人眼，很可能就这么提交了。
2. **表格行会污染标题**。抽取文本里的表格被切成句子后，
   `This | PET_B 5.94 3.17 ⋅ 10−13 | 7.37…` 一度成为节点名。
   scaffold 增加 `table` 标记后，表格只作为证据、不再做标题。

## 四、产物（每个案例）

| 文件 | 说明 |
|---|---|
| `mindmap.mm` | FreeMind / XMind / MindMaster 打开即可继续改 |
| `mindmap.opml` | 大纲工具通用交换格式 |
| `mindmap.md` | 纯文本大纲，diff 友好 |
| `mindmap.svg` | 矢量预览，一级分支分栏、节点右下角标原文编号 |
| `result.json` | case_id + 主结果 + 证据映射 + 不确定项 + 状态 |
| `blocks.json` / `blocks.md` | 句子块底账，复核用 |
| `check.md` | 10 项自查报告 |

## 五、复现

```bash
# 1) 切块编号
python3 scripts/mm_scaffold.py --in paper.md --out work --title "论文标题"

# 2) Agent 读 work/blocks.md，按 SKILL.md 写 work/nodes.json
#    或先用兜底草稿打底：
python3 scripts/mm_run.py --material paper.md --work work --out output

# 3) 校验（退出码 1 = 有 FAIL，按 check.md 改）
python3 scripts/mm_check.py --blocks work/blocks.json --nodes work/nodes.json --out work/check

# 4) 导出
python3 scripts/mm_export.py --nodes work/nodes.json --blocks work/blocks.json \
    --out output/mindmap --title "论文标题"
```

只依赖 Python 3.8+ 标准库，无第三方包。

## 六、没做到的事（如实列）

- **脚本不做语义理解**。兜底标题是句子截断，且会选中过渡句（实测 32 个节点里 11 个以
  `Despite` / `This` / `as` 开头）。必须靠 Agent 或人改写，这一点在 `SKILL.md` 里写成了硬规则。
- **中文不分词**。长术语（>20 字）会被截断，需要在 `note` 里补全称；
  英文句子的从句边界靠标点判断，遇到长复合句会切断修饰语。
- **只处理文本材料**。影像、光谱、显微图无法从文字还原，只能引用作者的读图结论。
- **没有做多文档合并**。当前一次处理一份材料；多篇综述的跨文对比只做到"同一张图上
  出现两个来源"，没有做文献间的证据权重。
- **A/B 的第二组对照（基础 Agent 无 Skill）没有独立运行**。本文的对照是
  "脚本兜底 vs 按 SKILL 改写"，两者都用同一套工具，差异只来自语义环节。
  真正的 A0 需要用同一模型在不加载 Skill 的条件下跑一遍，这件事没做，所以
  上表不能当成"加载 Skill 带来的提升"来读。

## 七、来源与贡献

- 案例论文为 Merillas 等 2026 年发表于 *Materials Today Sustainability* 34:101352 的

  引文均出自该文的机器抽取文本，未做改写；论文的方法、数据与结论归原作者。
