# 方案边界：本 Skill 管什么、不管什么、比什么强

## 1. 管什么（能力边界内）

四件可计算的事：

1. **术语锁定**：从原文抽取领域名词 → 建表 → 全篇锁定 → 逐条查漂移；
2. **数值落地**：原文每个数字都能在译文里以同值找到，量级换算按真实值核；
3. **段级对齐**：段号一一对应，引用/图表/公式/脚注标记按本体比对保留；
4. **语义边界**：否定、情态强度、限定条件的改动逐条列出。

## 2. 不管什么（明确不做）

| 不做 | 原因 |
|---|---|
| 判断译文"读起来好不好" | 风格判断不可计算，只能给规范清单供人工执行 |
| 替作者统一原文自身矛盾 | 那是学术判断，越权 |
| 补全缺失的引用信息 | 补错比缺更危险，一律 `needs_human` |
| 术语的学科最终裁决 | 表由人定；脚本只保证"表定了之后全篇一致" |
| 多语种混排的自动语种识别 | 只按任务声明的语向处理，识别不了的标 `skipped` |

## 3. 与通用翻译工具的差别

| 维度 | 通用翻译工具 | 本 Skill |
|---|---|---|
| 输入形态 | 一段文本 | 整篇材料 + 任务契约 + 语向 + 输出形态 |
| 术语 | 每次重新意译，前后不一致 | 先建表后锁定，漂移逐条列出 |
| 数值 | 会顺手取整、单位可能错配 | 逐值核对，量级换算按真实值，错项单独记 |
| 标记 | 常删引用与图表编号 | 按归一化键比对，丢失率可量化 |
| 段落 | 整篇平滑，段界模糊 | 段号主键，漏段/调序可定位 |
| 输出 | 一段译文 | 双语对照 + 术语表 + 三张台账 + 自查 |
| 可控性 | 黑箱 | 每项指标可重跑，阈值写在 `eval/rubric.json` |

## 4. 与"基础 Agent 直译"的差别

基础 Agent 的典型输出是"整篇看起来通顺的译文"，问题在于：

- 术语第 2 段叫"支架"、第 7 段叫"骨架"，读者要自己统一；
- `62.4` 变 `62`，`p = 0.012` 变 `p = 0.01`，作者必须逐个回原文核；
- `[12,13–15]` 与 `(Zhang et al., 2021)` 在译文里消失，归属断了；
- `may be associated with` 变成"导致"，结论被偷偷加强。

本 Skill 把这四类问题变成**可数的四个比率**，并给出达标线。基础 Agent 不给这些数，
所以"改没改好"无法判断；这里改没改好是 `validate_result.py` 的输出。

## 5. 增益的边界（诚实说明）

- 增益主要在**可核验性**与**返工量**，不在"文笔"。文笔仍靠人；
- 术语表建得好不好决定上限：表错，全篇一致地错；
- 极短材料（1–2 段）上，建表成本高于收益，本 Skill 的门槛（表 ≥12 条）会显得过重；
- 对诗歌、广告、口语对话等非学术文体，四把尺不适用，不要用。

## 6. 为什么不追求"端到端全自动"

全自动的前提是"能判断译得对不对"，而这需要领域判断。本 Skill 选择的是
**把不可判断的部分交给人（`human_review` + `uncertainty`），把可判断的部分做到可计算**。
这条边界就是它与"再包一层提示词"的本质区别：它产出的是可复核的记录，不是更长的译文。
