# 方法与实验章节写作（可复现 + 可追溯）

## 用途

把散落的实验材料（配置、日志、代码说明、数据说明）整理成**可复现、可追溯**的方法与实验章节。核心不是"写通顺"，而是四个可检查的性质：

- **写得全**：关键步骤、实验设置、参数、数据集与划分、对照与重复次数全部写到，不只留主干。
- **写得准**：参数取值、数据集版本与划分、训练/评测条件与配置文件、日志、代码一致，**不为段落顺畅补数值**。
- **做得着**：读者能按章节步骤与参数复做——版本、环境、随机种子、命令、数据获取方式给全。
- **说得住**：材料缺口与不确定处显式标注并交作者确认；限制条件指向具体失效场景，不是套话。

## 适用 / 不适用

适用：从配置/日志/代码说明撰写 Methods、Experimental Setup、参数表、数据集划分、对照实验、复现清单、Limitation。
不适用：无事实底稿的虚构方法描述；只要"讲个大概"的科普；结果/讨论章节（本 Skill 聚焦方法与实验）。

## 工作流

### 第 0 步：读事实底稿与约束
读 `/input/case.json` 与 `task.md`，确认写作范围（步骤 / 设置 / 参数 / 数据 / 对照 / 复现 / 限制）、受众、文体、格式。**先读实际材料文件**，不从领域标签推断内容（题面明确：不依据错误标签补造数据）。

### 第 1 步：抽取要素表（结构化底稿）
把材料里的要素抽取成结构化表，每类要素一条，附来源：
- **步骤**：每步的 `输入 / 操作 / 输出 / 判断条件`，有序，不把多步压成一句。
- **参数**：`名称 / 取值 / 单位 / 作用对象 / 来源`（配置文件 / 日志 / 代码 / 作者确认）。用 `scripts/extract_params.py` 从配置/日志文本抽取参数骨架。
- **数据集**：名称、版本、规模、预处理、划分比例、随机方式、各子集用途。
- **对照**：基线对象与版本、是否同预算、评价指标、统计方式、重复次数。
- **环境**：硬件、软件版本、随机种子、命令、数据获取方式。

### 第 2 步：对齐正文与数值
写正文时，每个数值/版本/条件必须能在第 1 步要素表里找到来源。写完后运行 `scripts/align_params.py <稿件要素表> <参数表>`：
- 正文出现的参数取值必须在参数表中存在且一致
- 参数表里的关键参数是否都在正文被覆盖
- 数值串位 / 无来源数值 → 判 `fabricated_value` 失败

### 第 3 步：复现清单核验
运行 `scripts/check_reproducibility.py <result.json>`，检查复现六要素是否齐全：代码版本、环境/依赖、随机种子、运行命令、数据获取、划分方式。缺失项列为 `reproducibility_gaps`，写入 `uncertainty`，不臆造。

### 第 4 步：缺口追问与限制
材料不足、配置冲突、参数无来源、数据集版本不明 → 生成 `questions_for_author`（追问清单），显式交作者确认，不自行补写。限制条件落到具体失效场景（如"当输入分辨率 <256 时插值失真"），不用"仍存在局限"这类套话。

### 第 5 步：契约自检
运行 `scripts/validate_result.py <result.json> --case <case.json>`，确认 `case_id`、状态、目标产物、事实来源映射、版本与边界字段齐全，通过后写入 `/app/output/result.json`。

## 输入输出

输入：`/input/case.json`（`case_id` / `output_contract` / 材料路径）+ `task.md` + 实际材料文件。
输出：`/app/output/result.json`，至少包含：

```json
{
  "case_id": "...",
  "status": "success | partial | unable | refused",
  "result": {
    "section": "可编辑的方法与实验章节正文",
    "elements": {"steps":[...], "parameters":[...], "dataset":{...}, "baselines":[...], "environment":{...}},
    "reproducibility": {"code_version":"...","env":"...","seed":"...","command":"...","data":"...","split":"..."},
    "questions_for_author": [...],
    "limitations": [...]
  },
  "sources": [{"element":"lr","value":"1e-4","source":"config.yaml:12"}],
  "uncertainty": ["..."],
  "changes": ["..."]
}
```

## 异常处理

- **材料缺失 / 参数无来源**：标 `questions_for_author` + `uncertainty`，状态 `partial`，不补数值。
- **配置冲突**：列出冲突项与各自来源，交作者裁定，不自行选一个。
- **数据集版本不明**：标为追问项，不臆造版本或规模。
- **权限不足 / 材料不可读**：状态 `unable`，说明原因与接管位置。
- **无法完成**：状态 `refused` 并给原因。

## 脚本

- `scripts/extract_params.py` — 从配置/日志文本抽取参数骨架（名称/取值/来源行）
- `scripts/align_params.py` — 正文数值与参数表对齐，抓无来源数值/串位
- `scripts/check_reproducibility.py` — 复现六要素完整性检查
- `scripts/validate_result.py` — 输出契约与状态自检

依赖：Python 3.9+，全部仅用标准库；路径相对本目录，不依赖个人文件。

## 限制

不提交预制答案；不为顺畅补数值；不臆造材料外的事实。脚本捕获"可机械判定"的硬伤（数值无来源、复现要素缺失、契约字段缺），语义级恰当性与限制条件的真实性需人工复核，在 `uncertainty` 如实说明。
