# 验收标准与盲评表

这是给「人」看的判定口径，与 `eval/rubric.json`（给机器看）一一对应。
用途两个：开发期自查；盲评时作为唯一评分依据，避免评分人各用各的标准。

## 1. 硬门槛（任一不过即不合格）

| 编号 | 门槛 | 判定方式 |
|---|---|---|
| H1 | 六类要素（步骤/设置/参数/数据/对照/复现限制）各自成段且顺序正确 | `element_coverage == 1.0` |
| H2 | 参数表 ≥5 行且每行标来源 | `param_rows >= 5` 且 `param_source_rate >= 0.8` |
| H3 | 正文数值与参数表一致，无表外数值 | `param_body_alignment >= 0.8` + 人工抽查 |
| H4 | 对照说明基线对象与版本、是否同预算、指标、统计方式、重复次数 | `baseline_coverage >= 0.66` |
| H5 | 复现清单含代码版本/环境/种子/命令/数据获取/划分 | `repro_coverage >= 0.66` |
| H6 | 限制落到具体失效场景（触发条件或阈值） | `limitation_specific == true` |
| H7 | 定稿无占位符、无材料外数值 | `placeholder_count == 0` + 人工抽查 `source-map.csv` |

## 2. 盲评表（主观项，5 分制）

评分人不知道版本来源，只按下列五项各打 1~5 分。

| 项 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 写得全 | 只有主干两三段 | 六类要素都有但参数与数据一笔带过 | 六类齐全，参数表、划分方式、对照条件、复现清单都在 |
| 写得准 | 数值与配置不符 | 大体一致但有表外数值 | 每个数值都能回到 config/log，正文与表一致 |
| 做得着 | 按章节无法复做 | 缺种子或命令，需追问 | 版本/环境/种子/命令/数据获取/划分给全，读者可照做 |
| 说得住 | 限制是套话 | 限制笼统（"存在局限性"） | 限制写到具体失效场景与适用范围 |
| 缺口处置 | 缺口被隐去 | 缺口写了但没追问 | 缺口列成 questions_for_author，blocking 项不掩盖 |

判定：五项均值 ≥4.0 且无单项 ≤2，视为「可用」；否则退回修改。

## 3. 分歧处理

- 两位评分人对同一项差 ≥2 分时，必须写出分歧理由（引用具体句子）。
- 分歧项单独记录，不用平均掩盖。
- 分歧超过 2 项，说明评分表本身有歧义，先改表再评。

## 4. 不许做的事

- 不拿本 Skill 作者的自评分当验收结果。
- 不把 `examples/` 里的示例成绩写成正式案例成绩。
- 不为凑 `manual_review_items = 0` 而隐藏真实缺口——该问作者的要问。
- 不为了凑 `param_rows` 而把同一参数拆成多行，或补出材料里没有的取值。
