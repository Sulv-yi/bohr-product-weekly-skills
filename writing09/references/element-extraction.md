# 要素抽取（Element Extraction）

## 目标
把散落在配置、日志、代码说明、数据说明里的要素抽取成**带来源**的结构化底稿，作为写正文的唯一事实依据。禁止"凭印象写"，禁止依据领域标签补造数据。

## 六类要素

### 1. 步骤（steps）
每步四要素：`输入 / 操作 / 输出 / 判断条件`。
- 有序编号，不把多步压成一句。
- 判断条件写清（如"若验证损失连续 5 轮不降则早停"）。

### 2. 参数（parameters）
每条：`名称 / 取值 / 单位 / 作用对象 / 来源`。
- 来源是硬要求：配置文件名 + 行号、日志名 + 时间、或"作者确认"。
- 正文引用的每个数值都要能在参数表找到。

### 3. 数据集（dataset）
名称、版本、规模、预处理、划分比例、随机方式/种子、各子集用途。
- 版本与划分是复现成败关键，缺一即追问，不猜。

### 4. 对照（baselines）
基线对象 + 版本、对照条件是否同预算、评价指标、统计方式（均值±标准差 / 显著性检验）、重复次数。
- "优于基线"必须可比对，不能是无依据断言。

### 5. 环境（environment）
硬件、OS、语言/框架版本、依赖、随机种子、运行命令、数据获取方式。

### 6. 限制（limitations）
落到具体失效场景与适用范围，如"当序列长度 >512 时显存溢出""仅在英文语料验证"。

## 抽取原则
- **来源优先**：宁可标"来源缺失，待确认"，也不填一个看似合理的数。
- **原样保留**：数值、版本、单位按材料原样抽取，不在抽取阶段做换算或润色。
- **冲突并列**：同一参数在不同材料不一致时并列记录各自来源，不自行选。

## 抽取工具
`extract_params.py <material.txt> --out params.json` 从文本抽取 `key=value`、`--flag value`、常见超参（lr/epochs/batch_size/seed 等）骨架并标注来源行号。它是**候选**，需人工确认作用对象与单位。
