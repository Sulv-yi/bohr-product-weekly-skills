# 可复现性与限制（Reproducibility & Limitations）

## 复现六要素（缺一即追问）

| 要素 | 内容 | 缺失后果 |
|---|---|---|
| 代码版本 | commit / tag / 仓库地址 | 无法确定用哪版代码 |
| 环境依赖 | OS、语言/框架版本、关键库及版本 | 环境不一致导致结果偏差 |
| 随机种子 | 各阶段 seed 与设定方式 | 结果不可复现 |
| 运行命令 | 训练/评测的完整命令与参数 | 读者不知如何执行 |
| 数据获取 | 数据来源、版本、下载/申请方式 | 拿不到同份数据 |
| 划分方式 | 划分比例、随机方式、各子集用途 | 划分不同导致对比无效 |

`check_reproducibility.py` 逐项检查 `result.reproducibility`，缺失项写入 `uncertainty` 与 `questions_for_author`，状态降为 `partial`。

## 训练 / 验证 / 测试分离
分别描述三流程，写清各自输入、条件与用途；避免把验证集调参和测试集评测混写（条件串台会让结论失真）。

## 对照实验可比性
- 基线对象与版本明确
- 对照条件同预算（同数据、同计算量/时间）
- 评价指标与统计方式写明（均值±std、显著性检验）
- 重复次数给出

## 限制条件的写法
落具体失效场景，不用套话。

反例（套话）：
> 本研究仍存在一定局限性，未来工作将进一步改进。

正例（具体）：
> 方法仅在英文科学文献摘要上验证；当输入含大量数学公式（占比 >15%）时，术语抽取准确率下降约 20%，因公式中的符号被误判为术语。

## 异常处理
- 材料不足以给全六要素 → 已给部分照写，缺失标追问，状态 `partial`
- 配置冲突 → 并列来源，交作者裁定
- 数据集版本不明 → 追问，不臆造版本/规模
