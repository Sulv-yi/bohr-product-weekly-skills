## 已知边界（如实记录，未在本机样本上解决）

1. **双栏论文里「跨栏并排」的表格**：表格与正文处在同一视觉行，按坐标栅格切分会被正文打断，此时如实记 `unparsed_tables` 并给出原因，不返回错误的单元格。
2. **扫描件/无文字层**：不做 OCR 猜测，逐页记 `unreadable_pages`；需要文字时由上层决定是否接 OCR。
3. **占位型 PDF**（记录页写着原文文件缺失）：如实输出所述内容并标注「材料本身不含论文正文」，不虚构论文内容。
4. **参考文献切条目**：编号缺失时会退化为按作者字母起首切分，条目数与原文可能有偏差，已在 `reference_unparsed` 计数。

## 表格重建：列锚点聚类（2026-11-28 复测）

改前的实际表现：9 页 Wiley 双栏论文有 5 张表（TABLE 1–5），只解出 1 张，另 4 张
静默消失。原因有两个，都是实现层面的：

1. **题注按「行」找，双栏版面必然找错**。题注在右栏 x=306.7，同一 y 的左栏是正文，
   整行文本以正文开头，`re.match` 永远匹配不上；退到版面切分后拿到的又是正文串栏。
2. **按行切缝遇到纵向合并单元格就整表丢弃**。合并单元格让某几行的格子特别宽，
   列数与前几行不一致，`mode_cols` 一致性检查一判就废。

改法：

- 题注按**块**定位（逐块匹配 `^TABLE n`），再取 `x >= 题注 x` 的横坐标带，避开左栏；
- 列边界改为**列锚点聚类**：全块左边缘按 10pt 容差聚类，出现 ≥2 次即成列锚点，
  表头独占的列也强制保留。合并单元格只会让某些行缺值，不会移动其余行的边界；
- 表格区域取到「首个单块长句行」为止（双栏版面上每栏一行就是正文片段）；
- 栅格之外并给 `raw_rows`（按行原文）：PDF 把相邻列合并成一段文本流时，
  栅格会留空格位，原文至少保住数据。

复测（`local-tests/case1/paper.pdf`，9 页）：

| 表 | 改前 | 改后 |
|---|---|---|
| TABLE 1 | 丢弃 | 19×3，表头 `PI / λ max (nm) / ε max (L/mol · cm)`，附 19 行原文 |
| TABLE 3 | 丢弃 | 4×4，表头 `Photoinitiating System / aN (G) / aH (G)` |
| TABLE 2 / 4 / 5 | 静默消失 | 保留条目，`cell_confidence: unparsed` + 原因 |

题注识别也从 19 条降到 14 条：正文引述句（`Table 5: The table shows that ...`）
和同号重复题注（`Table 5` 与 `TABLE 5`）都不再各算一条。

局限（写进 `uncertainty`，不掩盖）：TABLE 1 的数据行在 PDF 里被合并成单个文本流
（`BP 250 17 750`），栅格只能还原出 3 列中的 2 列有值，需要人工按 `raw_rows` 复核。
