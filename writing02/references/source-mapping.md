# 事实与来源映射规范

## 为什么需要

题面明确要求"完成产物，也保留来源"。润色不是凭空改写——每一处数字、术语、引用、关键论断都要能指回原文位置，第三方才能判断有没有改坏。

## sources 记录格式

```json
{"claim": "样本量 n = 120", "location": "第2段第3句", "type": "number"}
{"claim": "方法称为 deep neural network (DNN)", "location": "第1段第2句", "type": "term"}
{"claim": "与已有研究一致", "location": "第4段第1句，引文 [7]", "type": "citation"}
{"claim": "该方法在测试集上表现更优", "location": "摘要第3句", "type": "fact"}
```

`type` 取值：`fact` / `number` / `term` / `citation` / `figure_table` / `hedge`

## 定位方式

按可用性优先选择：
1. 有句号：第 N 段第 M 句
2. 有行号：第 N 行
3. 有字段名（结构化输入）：`<field>[i]`
4. 都无：用原文片段作为锚点，格式 `锚点:"原文前20字"`

## 不可新增

- 不得写入原文没有的数字、单位、机构名、人名、年份
- 不得补造引用；原文引用缺失时在 uncertainty 标"引用缺失，需人工补充"
- 不得把"相关"改成"因果"，即使常识上说得通
- 不得把未报告的数据写成"无显著差异"——未报告就是未报告

## 人工确认项

以下内容即使看起来可以改，也列入 uncertainty 与 `needs_confirmation`，不擅改：
- 术语表未覆盖的同义混用
- 原文内部矛盾的数字或结论
- 引用编号在原文中不连续或重复
- 目标文体与原文风格明显冲突
- 公式、符号含义需要领域知识判断的情况
