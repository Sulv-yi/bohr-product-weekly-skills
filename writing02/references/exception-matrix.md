# 异常处理矩阵

润色任务真正翻车的地方，通常不是语法，而是输入不干净、约束互相冲突、或者根本不该润色。
本文件规定：**识别信号 → 处置动作 → 写进哪个字段**。原则是先标注、再处理，不静默猜测。

| 情形 | 识别信号 | 处置 | 输出位置 |
|---|---|---|---|
| 超长输入（超出预算） | 字数 > 单次预算可处理量，或段落数 > 60 | 按章节切块，逐块处理，最后合并；未处理部分显式列出 | `status=partial`，`uncertainty` 写未覆盖范围 |
| 编码混乱 | 出现 `\ufffd`、乱码串、UTF-8/GBK 混排 | 先试 UTF-8 → GB18030 回退；仍失败则保留原字节转义并标注 | `uncertainty` 记文件与段号 |
| 公式与引用混杂 | 段内 `$...$`、`\(...\)`、`\cite{}`、`[n]` 与正文交织 | 公式与引用标记**原样保留**，只改其外层自然语言；不重排编号 | 改动记录里 `change_type=grammar/syntax`，不标 `citation` |
| 中英日混排 | 同段三种以上书写系统 | 不做跨语言改写；只统一标点与空格；术语表分别登记 | `uncertainty` 标"混排段落仅做标点统一" |
| 术语表内部冲突 | 同一 term 映射到两个 target，或两个 term 映射到同一 target | **不自行裁决**。列出冲突对，选覆盖原文更多者作默认并标注 | `status=partial`，`questions_for_author` 列冲突项 |
| 目标文体不明 | 任务说明未给 genre，材料特征互相矛盾 | 按最保守的"期刊论文正文"处理，并声明假设 | `uncertainty` 写明"文体按期刊论文假设" |
| 纯问答 / 纯翻译 / 纯格式转换 | 输入没有"改写现有文本"的诉求 | **不触发本 Skill**，直接回答 | 无输出文件（见 SKILL.md 触发条件） |
| 原文本身有事实错误 | 数字与单位明显不自洽、引用与论断不符 | 不改事实，只标注；不借润色之机修正数据 | `uncertainty` + `questions_for_author` |
| 重复运行结论漂移 | 同一段三次润色结果差异 > 30% | 以第一次为基准重跑，记录漂移幅度 | `scorecard.json` 附 `drift` 说明 |
| 术语表为空 | 材料领域术语密集但没给表 | 先自动抽取候选术语（出现 ≥3 次的名词短语）供确认，不直接定译 | `questions_for_author` 列候选 |

## 处理顺序

1. 先判定"该不该触发"（最后一行优先于其它）。
2. 再做输入体检（编码、长度、混排、公式）。
3. 再读术语表，冲突先记下来，不阻断流程。
4. 最后才进入逐段润色。

任何一步的降级都要落在 `result.json` 的 `status` 与 `uncertainty` 上，
不允许"看起来完成了"但实际只处理了一半。
