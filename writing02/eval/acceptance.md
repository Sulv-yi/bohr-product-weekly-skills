# 验收标准与盲评表

这是给「人」看的判定口径，与 `eval/rubric.json`（给机器看）一一对应。
用途有两个：开发期自查；盲评时作为唯一评分依据，避免评分人各用各的标准。

## 1. 硬门槛（任一不过即为不合格）

| 编号 | 门槛 | 判定方式 |
|---|---|---|
| H1 | 原文每一段都有对应润色段，无漏段 | `segment_coverage == 1.0` |
| H2 | 数字、单位、引用编号、图表指向在改文中全部对得上 | `invariant_conservation == 1.0` |
| H3 | 每一处改动都有「原文 / 改文 / 类型 / 理由」四元组 | `edit_note_coverage >= 0.9` |
| H4 | 术语表里的每个术语在改文中只用一种译法 | `term_uniqueness == 1.0` |
| H5 | 没有把不确定的东西写成确定（限定词守恒） | `hedge_conservation == 1.0` |

## 2. 盲评表（主观项，5 分制）

评分人不看版本来源，只按下面五项各打 1~5 分。

| 项 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 语法正确 | 仍有硬错误 | 明显错误已改 | 读不出非母语痕迹 |
| 语域贴合 | 仍像口语/机翻 | 基本符合文体 | 与目标期刊同调 |
| 语义保持 | 主张被改变 | 大意保留，强度有偏移 | 强度、否定范围、因果/相关区分精确保持 |
| 术语一致 | 同概念多种写法 | 大体一致 | 全篇统一，缩写首次出现规范 |
| 编辑克制 | 整段重写 | 有过度同义替换 | 最小编辑，只动该动的 |

判定：五项均值 ≥4.0 且无单项 ≤2，视为「可用」；否则退回修改。

## 3. 分歧处理

- 两位评分人对同一项差 ≥2 分时，必须写出分歧理由（引用具体句子）。
- 分歧项不取平均掩盖，单独记录在 `uncertainty`。
- 分歧超过 2 项，说明评分表本身有歧义，先改表再评。

## 4. 不许做的事

- 不拿本 Skill 作者的自评分当验收结果。
- 不把示例集的成绩写成正式案例成绩。
- 不为凑 `manual_review_items=0` 而隐藏真实的材料缺口——该问作者的就要问。
