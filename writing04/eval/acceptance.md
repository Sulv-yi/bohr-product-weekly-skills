# 验收标准与盲评表

这是给「人」看的判定口径，与 `eval/rubric.json`（给机器看）一一对应。
用途两个：开发期自查；盲评时作为唯一评分依据，避免评分人各用各的标准。

## 1. 硬门槛（任一不过即不合格）

| 编号 | 门槛 | 判定方式 |
|---|---|---|
| H1 | 交付可编辑稿件，不是只交引用记录 | `manuscript_delivered == true` |
| H2 | 每条引用有论断原文，位置精确到句 | `claim_rate == 1.0` 且 `claim_location_rate == 1.0` |
| H3 | 每条引用写明"为何该文献支撑这句话" | `match_basis_rate == 1.0` |
| H4 | 编号连续、无悬空引用 | `numbering_continuous == true` 且 `dangling_count == 0` |
| H5 | 文献键都能回溯到条目 | `ref_resolved_rate == 1.0` |
| H6 | 去重的合并/分开/待定都带判据 | `dedup_*_basis_rate == 1.0`（该项为空时须在 uncertainty 说明） |
| H7 | 格式转换给出字段映射与保留字段 | `format_mapping_fields >= 1` 且 `preserved_fields >= 1` |
| H8 | 无占位符残留 | `placeholder_count == 0` |

## 2. 盲评表（主观项，5 分制）

评分人不知道版本来源，只按下列五项各打 1~5 分。

| 项 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 挂得对 | 引用挂在段尾凑数 | 位置对但 match_basis 牵强 | 引用落在具体论断句上，match_basis 说得清这篇文献哪一点支撑它 |
| 编得顺 | 编号乱、有悬空 | 连续但样式混用 | 编号连续、无悬空、文末条目全被引用 |
| 收得净 | 重复条目未处理 | 合并了但没给判据 | 合并/分开/待定都有可复核判据，歧义项交人工 |
| 对得上 | 文献键指错条目 | 条目对但缺关键字段 | 每条可回溯、DOI/卷期页齐全，缺字段如实标注 |
| 交付形态 | 只给建议不给稿件 | 给了稿件但缺记录 | 稿件与记录同时交付，记录可逐条核对 |

判定：五项均值 ≥4.0 且无单项 ≤2，视为「可用」；否则退回修改。

## 3. 分歧处理

- 两位评分人对同一项差 ≥2 分时，必须写出分歧理由（引用具体句子）。
- 分歧项单独记录，不用平均掩盖。
- 分歧超过 2 项，说明评分表本身有歧义，先改表再评。

## 4. 不许做的事

- 不拿本 Skill 作者的自评分当验收结果。
- 不把 `examples/` 里的示例成绩写成正式案例成绩。
- 不为凑 `manual_review_items = 0` 而隐藏真实缺口——该问作者的要问。
- 不为了凑 `cite_count` 而把一句话拆成两条引用，或给不需要出处的句子硬挂文献。
