# 与已有方案的边界

这一节回答一个问题：**这个 Skill 到底补了什么，哪些事它不该做。**
只写有依据的比较；没有实测过的对象，不声称优于它。

## 1. 比较对象与适用位置

| 方案 | 擅长 | 在本任务上的缺口 | 本 Skill 的位置 |
|---|---|---|---|
| 基础 Agent（不加载 Skill） | 按字面把引用编号重排、按模板拼一条参考文献 | 引用挂在段尾凑数；不说明"为何这篇支撑这句"；去重常把同名不同文合并；编号与文末条目双向对不上时不报 | 把四性质变成可计算门槛：位置精确到句、match_basis 必填、去重三分判断必须带判据、悬空/未引用双向检查 |
| 文献管理软件（Zotero/EndNote） | 管元数据、按样式出参考文献表 | 只管"格式对不对"，不管"这句该不该引这篇"；不判断两条是不是重复；不检查正文编号连续性 | 借用其元数据与样式能力，补上论断-文献绑定与双向一致性 |
| 期刊模板/投稿系统校验 | 检查参考文献样式、字数、图表格式 | 不读内容，无法判断论断与文献是否匹配；不处理去重歧义 | 与模板校验互补：模板管形式，本 Skill 管绑定与可回溯 |
| 通用脚本（正则重排编号） | 批量改编号 | 改完不校验悬空与未引用；合并条目无判据 | 重排后立刻做双向检查，失败项逐条列出 |

结论：本 Skill 不与上述方案竞争"样式合规"，它竞争的是**可核查**——
每条引用都能回答"挂在哪句、为什么是这篇、文献条目在哪、编号对得上吗"。

## 2. 基础 Agent 难以稳定做到的四个性质

1. **挂得对**：要求每条引用有 `claim` 原文 + 精确到句的 `claim_location` + `match_basis`。
   位置落在段尾、claim 不在稿件原文、自报 position_ok=false 都会在门槛里报错。

2. **编得顺**：正文编号与文末条目双向检查——悬空引用（正文有、文末无）与未引用（文末有、正文无）
   分别列出，`continuous` 由实际编号序列判定而不是自报。

3. **收得净**：去重必须给出 `merged / kept_separate / pending` 三分判断，
   合并要有 DOI 或题名+卷期页的判据；"同名作者不同文"要明确判为不合并。

4. **对得上**：文献键必须能在文献库快照里找到，格式转换要给出字段映射与保留字段（DOI/卷期页）。

## 3. 方法取舍（为什么这样做）

| 取舍 | 选择 | 理由 |
|---|---|---|
| 交付形态 | 稿件 + 结构化记录同时交 | 只交记录读者没法用；只交稿件无从复核 |
| 核验时机 | 生成后再核验，生成阶段不自我盖章 | 边写边判会把自己的猜测当证据 |
| 去重 | 歧义项进 pending，不自动合并 | 误合并两条不同文献比漏合更难发现 |
| 缺字段 | 留空 + uncertainty，不补造 DOI | 编造 DOI 会污染下游所有引用检查 |
| 自评 | 用脚本算指标 | 文字自述不可复核 |

## 4. 不声称的部分

- 不声称能判断文献内容是否真的支撑论断：`match_basis` 是作者写的理由，脚本只保证它存在且形式可核，真伪要人读原文。
- 不声称无网络时能核验 DOI 真实性：只做格式与字段一致性检查。
- 不声称零人工：`pending` 与 `uncertainty` 允许非零，那是诚实缺口。
- 不声称已在平台固定案例上取得某个具体分数。
