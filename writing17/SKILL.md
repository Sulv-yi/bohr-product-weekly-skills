# 科研成果转化写作 Skill

把论文、技术报告改写成面向特定读者的稿子（科普文 / 项目材料 / 摘要），
并保证：读者读得懂、证据留得住、论断说得准、原作者接得住。

## 何时用

- 把论文摘要 / 技术报告改成面向公众或管理者的稿子
- 把一篇论文的方法与结论改写成项目申报材料
- 把同一成果写成两个读者层级的版本，要求数据不打架

不适用：需要新做实验才能回答的问题；原文本身缺失关键数据时的「无中生有」式改写。

## 动笔前预算表

先按输入规模定目标，再动笔。写不到预算下限就说明取舍过头，写到上限以上说明没收紧。

| 源文规模 | 目标字数 | 节数 | 类比/解释 | 改动账条目 | 溯源覆盖 |
|---|---|---|---|---|---|
| ≤1000 字（摘要） | 900–1300 | 4–6 | ≥2 | ≥6 | ≥80% |
| 1000–2500 字（一节/一段报告） | 1300–2200 | 6–9 | 2–4 | ≥8 | ≥80% |
| 2500–6000 字（全文） | 2000–3500 | 8–12 | 3–6 | ≥12 | ≥80% |

数值预算另算：源文里带单位的数值，保留率 **≥90%**；限定条件（仅/只/限于/样本/体外/短期）保留率 **≥70%**。
这两项不受字数预算影响——压字数不能压证据。

## 执行步骤

1. **读源文，先列三张清单**（不写正文）
   - 数值清单：带单位的数 + 比较基准 + 样本量
   - 限定清单：仅/只/限于/条件下/体外/短期/尚未
   - 缩写清单：全大写缩写 → 中文全称
2. **定读者与阅读目的**，在成稿开头显式写出（脚本会检查这两句在不在）。
3. **写正文**，按 `references/audience-and-depth.md` 的深度规则取舍：
   先讲"这是什么现象"，再讲"怎么测的"，最后讲"边界在哪"。
4. **逐句挂溯源**：含数值或结论的句子后面加 `【源：源文 §x 图 y】`。
   表格整段挂一次即可（按段落判，不要求逐行）。
5. **写改动清单**：正文段落数 ≥80% 要有对应条目，格式 `- [改:理由]` 或清单章节条目。
6. **跑门槛**，不过就按报错逐条改。

## 五条硬门槛

| 门槛 | 阈值 | 脚本 |
|---|---|---|
| 缩写首次出现须展开 | ≥90% | `abbrev_check` |
| 带单位数值保留 | ≥90% | `retention` |
| 限定条件保留 | ≥70% | `retention` |
| 限定语不丢（源文 hedge 句 → 成稿仍有） | ≥80% | `hedge_retention` |
| 论断不越界（强断言须有 hedge 或溯源） | 0 句 | `strength_align` |

辅助门槛：长句占比 ≤30%、术语密集句 ≤35%、术语漂移 0、改动账覆盖 ≥80%、溯源 ≥80%、
类比 ≥2 处、占位符 0。

## 异常与降级

| 情况 | 处理 |
|---|---|
| 源文缩写没有全称 | 不展开，改写成中文描述；在 uncertainty 里记「源文未给全称」 |
| 源文数值互相矛盾 | 两个都写，标注「源文自相矛盾，未作取舍」 |
| 源文没有图表编号 | 图表门槛自动跳过（分母为 0 时记 100%） |
| 目标读者与源文结论冲突（如公众需要确定性） | 保留 hedge，另加一句「这意味着什么、不意味着什么」 |
| 材料不足以支撑科普化 | 降级为「问答式说明」，逐条回答读者会问的问题，不编背景 |

详见 `references/edge-cases.md`。
