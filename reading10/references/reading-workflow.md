# 阅读与笔记工作流细则

## 论文类型与骨架差异

- 实验论文：研究问题→数据→方法/实验条件→结果→讨论→局限。findings 的 conditions 重点记实验条件、样本范围、显著性口径。
- 理论/综述：问题→概念框架→论证链→结论→开放问题。章节可能没有独立"结果"节，按实际 outline 走。
- 短通讯/摘要型：章节少，premises 与 limitations 常散在正文，需从字里行间提取并标注来源。
- 非英文：保留原文术语做 term，中文译名放 aliases。

## 章节对齐要点（对得上）

1. 章节来自 `build_outline.py` 识别的真实标题，不用通用模板。
2. 若论文把"方法"嵌在"实验"节里，就按 outline 记为同一节，不强行拆分。
3. 双栏论文注意 across-column 续接：`block_section` 把块映射到节，`order` 给出阅读顺序。
4. 编号小节（2.1/2.2）level>1，可作为大节的子笔记，但 section_id 仍唯一。
5. `--strict-align` 要求覆盖 outline 全部章节；确实无内容的节也要写一条说明"本节无实质内容/未报告"。

## 留得住：五要素齐全

做完卡片后逐项自查：
- 研究问题：作者想解决什么？是否明确？
- 数据：数据集名、规模、来源、划分方式是否记录？
- 方法：关键方法、实验条件、超参是否记录？
- 主要发现：每条结论的成立前提/适用范围是否写进 conditions？
- 局限：作者自述局限 + 你能识别的边界（后者标注为推断）。
- premises：把"如果…则结论成立"的前提单列，避免结论被断章取义。

## 找得回：锚点质量

- 一个 source 的 quote 尽量短而唯一（10–60 字），便于逐字匹配。
- 数字、百分比、结论性判断必须有 source；观点性总结可无 source 但要在 summary 里说明是归纳。
- quote 找不到（verify 报 traceable failed）常见原因：抄错、改写、翻译了原文、跨行合并。修到能在原文匹配为止。

## 用得上：知识点设计

- 一条知识点 = 一个可独立检索的概念/变量/方法/结论。
- 缩写与全称合并为一条，全称作 term、缩写作 alias。
- 同义表述归并，但要注明出处术语差异。
- 定义尽量用作者原意，标 source_ids；自己的延伸写进 definition 但注明"笔记补充"。

## 增量与诚实

- 先落一版完整 result.json（哪怕很多字段为 skeleton），再逐节填充，每次改在 changes 留痕。
- 材料读不出/冲突，写 uncertainty，不猜。
- 预算内（64 请求/900s）优先保证 success 的核心笔记，再补知识点与措辞。
