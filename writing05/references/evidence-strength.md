# 证据强度：怎么定级、怎么让正文配得上这个级别

机器可读的口径在 `assets/strength-table.json`，本文说明为什么这么分、以及落地时容易错的地方。

## 为什么是四档而不是百分制

百分制会制造"73 分证据"这类无法复核的数字。四档的每一档都能用一个可观察的属性判定：
研究设计类型、样本量、是否重复验证、是否有领域共识。同一段原文，两个人按同一张表
应该得出同一档；得出不同档时，分歧点是"某线索是否命中"，可以就地讨论，而不是各说各话。

## 定级顺序（不可跳步）

1. 先看**设计线索**：系统综述 / 随机对照 / 多中心 → strong；队列 / 对照实验 / 重复
   验证 → moderate；单例 / 体外 / 预印本 / 单次实验 → weak。
2. 再看**样本线索**：命中 `n=…` 时，`n < 10` 一律降到 weak（哪怕是随机对照）。
3. 两条线索都没有 → `insufficient`，并打 `needs_review` 标记。
   **不允许默认 moderate**：默认中间档会让整篇看起来"都还行"，这是最典型的失败模式。
4. 多条证据支撑同一论断时取最低档（短板原则），理由写进 `strength_basis`。

脚本已实现这套规则：

```bash
python scripts/claim_split.py --quote "随机对照试验，纳入 1200 例患者" \
    --claim "该方案可降低复发率" --grade
# -> strength=strong, basis=["设计线索 随机对照", "样本量线索 1200 例"], hedge_ok=true
```

`--grade` 的输出是**建议**。使用者可以改判，但必须在 `strength_basis` 写明改判理由，
否则 `selfcheck.md` 会显示该条只有脚本依据、没有人工依据。

## 正文表述怎么配

| 等级 | 允许的写法 | 禁止的写法 |
|---|---|---|
| strong | 「X 降低 Y」「多项研究一致显示…」 | 超出证据范围的推广（如跨物种、跨体系） |
| moderate | 「在本研究条件下」「在该体系中观察到」 | 「证明」「必然」「完全」「唯一」 |
| weak | 「可能」「提示」「初步显示」「尚不能排除」 | 「表明」「证实」「领域共识」 |
| insufficient | 「尚不清楚」「有待验证」，或移出正文 | 任何肯定句 |

脚本会检出绝对化词与 hedge 的缺失：

```bash
python scripts/claim_split.py --quote "单中心、n=6 的体外实验" \
    --claim "该机制已被证实" --grade
# -> strength=weak, hedge_ok=false（含绝对化断言，但证据为 weak）
```

`hedge_alignment` 就是"相称的论断占已判定论断的比例"。它掉下来通常不是写错字，
而是**摘要或结论段复述了正文里的弱证据却没带限定语**——这处最常被漏检。

## 常见误判

- **把综述当强证据**：综述本身是二手证据，若综述明确指出领域内结论冲突，
  应按 conflict 处理并在 `conflicts` 里列出，而不是当成 strong 直接引用。
- **把大样本当强设计**：横断面调查 n=5000 仍是 moderate，因为没有时间先后。
- **把重复测量当重复验证**：同一批样本测三次是技术重复，不是独立复现；前者不升档。
- **把预印本当已发表**：预印本一律 weak，且需在 uncertainty 标注版本与日期。
- **撤稿/更正**：若来源被撤稿或更正，直接判 `insufficient` 并从正文移除该论断的依据。
