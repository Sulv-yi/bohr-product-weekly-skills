# 方案边界：本 Skill 给了什么、没给什么

写这份文件的用途不是论证"我们很强"，而是让评审能判断创新点落在哪、边界在哪。
凡是本 Skill 做不到的，下面都写明做不到。

## 对照一：不加载 Skill 的基础 Agent

| 维度 | 基础 Agent | 本 Skill | 差在哪 |
|---|---|---|---|
| 论断切分 | 给一段成稿，不区分哪句是可检验断言、哪句是过渡句 | `claim_split.py` 按句末切分 + 断言线索过滤，产出带 `char_start` 的单元表 | 有编号才能逐条核对；没有编号时"每条论断"这个要求在操作上无法执行 |
| 强度判定 | 靠语感给"强/中/弱"，同一段文字两次回答不一致 | 规则推导：设计线索 → 样本线索 → 复现线索，命中不了写 `insufficient` | 可复核：两个人按同一张表得到同一档；不一致时能定位到哪条线索没命中 |
| 表述相称 | 常把弱证据写成肯定句（摘要/结论段尤其明显） | 机器校验 `hedge_ok`，`weak` 无限定语、`moderate` 含绝对化词都判 fail | 这是基础 Agent 最稳定的失败模式，也是本题"说得准"的直接扣分点 |
| 冲突处置 | 通常不写，除非提示里强调 | 强制 `conflicts[]` 或 `conflict_search_note`，为空即判未处理 | 避免"隐去反面证据"这一项被扣分 |
| 可核验 | 交一份成稿 | 成稿 + 论断清单 + 证据表 + 自检表四件 | 第三方可只读附件完成复核，不必重跑模型 |

基础 Agent 的实际短板集中在**一致性**：同一批材料重复运行时，绑定率与相称率波动大。
本 Skill 把这三件事变成脚本判定，波动来自输入而不是心情。

## 对照二：通用学术写作助手（在线润色/生成类）

它们优化的是**可读性与流畅度**，对"这句的依据在哪里"通常只给到"有引用"这一层。
本 Skill 优化的是**可追溯性**：每条论断要有定位到段落/页的原文摘录，
引用要在正文中有编号，编号要对得上证据表。二者不冲突，但目标不同——
拿润色助手做本题，典型的失败是"文笔很好，但抽一句问依据答不出来"。

## 对照三：文献管理/引文核查工具（Zotero、查重、引文校验服务）

它们能校验条目真实性与著录格式，但**不判断"这篇文献是否支持这句话"**。
本 Skill 的匹配依据落在 `relation` 与 `strength_basis` 上，正是这一段的前后衔接：

- 引文工具管「文献存在且著录正确」；
- 本 Skill 管「文献支撑哪条论断、支撑到多强、正文表述是否匹配」。

两者应当串联使用，本 Skill 不重复实现元数据抓取。

## 明确做不到的

1. **不做全文语义蕴含的严格判定**。`relation` 与 `strength` 是规则 + 人工复核的产物，
   不是 NLI 模型的输出。摘录与论断的"是否真的支持"仍需人读一遍。
2. **不做数据库检索**。只处理材料里给出的文献；材料没给的不会去编。
3. **不做跨语言证据对齐**。原文为英文、成稿为中文时，`quote` 保留原文，
   对齐靠人工，脚本只校验 `quote` 是否能在材料里定位到。
4. **强度分级表是学科无关的粗口径**。医学的 RCT 与材料学的对照实验不等价，
   需要按学科替换 `assets/strength-table.json` 里的线索词；替换后要重跑 A/B 对照，
   因为档位分布会变。
5. **不判断学术不端**。重复发表、图片复用这类问题不在范围内。

## 创新点收敛成一句

把"每条有依据的话都能被指认依据在哪、依据多强、正文配不配得上"从写作建议
变成三个可跑脚本：切分（claim_split）、定级（grade/hedge_ok）、核算（evidence_gate），
并让三者共用同一份 `result.json`，从而可以被第三方用同一条命令复算。
